# Flow retrospective

This file belongs to the project. Roclec creates it once and never overwrites it, so edit it freely.

The "Flow learning" section of the generated flow view (`docs/flow.md`, or the `view` path in `.roclec/flow.toml`) already lists what the records show: flow revisions and the process FUTs they address, rejections by stage, findings, stages without AI and agent sessions. Run `roclec views --write` to refresh it. Use this file for what the records cannot show.

Add one entry per retrospective, newest first. When a reflection leads to a change in the flow, capture it as a process FUT (`fut capture` with scope `process`) and cite it when the flow is agreed again.

## YYYY-MM-DD — Period or release reviewed

### What did not work as expected

- Where the flow caused friction, rework or waiting, and in which stage.

### What would change with a larger team

- Roles, checkpoints or reviews that would need to change with more people.

### AI-use decisions to revisit

- Stages that should move between AI and a person, and why.
